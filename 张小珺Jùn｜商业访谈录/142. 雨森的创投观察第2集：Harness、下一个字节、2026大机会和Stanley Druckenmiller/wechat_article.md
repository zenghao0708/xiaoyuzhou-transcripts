# 听完戴雨森这期：AI 创业别只盯着模型

我把张小珺这期《雨森的创投观察》第 2 集转成了文字稿。两个多小时听下来，我最想记下来的，是戴雨森复盘自己上一期判断时的那句话：

Strong opinions, weakly held。

有强观点，但不要被强观点绑住。

这句话放在投资里有用，放在 AI 创业里也有用。过去半年，OpenAI、Gemini、Anthropic 的叙事轮流占上风。去年底大家看 OpenAI 的 DAU 和订阅收入，今年初看 Gemini 的模型追赶，三四月又开始看 Claude Code 和 Anthropic 的企业收入。到现在，Codex 又追回来一段。

这个行业的问题就在这里：变化太快，很多判断不会一次说准。更好的做法是，把自己为什么这么判断写清楚，然后持续看前提有没有变。

## Coding 把回报时间线往后推了

戴雨森上一期谈过 2026 年的 return 问题。听完这一期，我理解他并没有完全推翻原判断。

C 端订阅没有想象中那么容易继续提价。广告和电商也不是把入口放进 ChatGPT 就能自然跑起来。互联网公司当年从流量到广告、电商，花了很多年才磨出来。AI 产品也一样，不会因为“入口很大”就马上变成印钞机。

但他看错了一块：coding。

Claude Code 这类产品把 AI 从聊天框里拽出来，放进了真实工作流。用户愿意为能完成任务的系统付更多钱，企业也更容易计算价值。这个变化让“AI 回报什么时候出现”这件事变复杂了。

这里有个很好的比喻：AI 能力像水烧开。99 度时你能感觉它快了，但还没有蒸汽机。到了某个版本，任务突然跑起来，价值就会跳出来。事前很难精确知道是哪一版。

## Harness 不是壳

这期反复谈到一个词：Harness。

如果只把它理解成“模型外面包一层产品”，就太轻了。好的 Harness 包含很多东西：上下文怎么组织，工具怎么调用，任务怎么拆，权限怎么管，失败后怎么恢复，用户轨迹怎么回流，系统如何越用越稳。

这也是为什么“套壳”这个说法越来越不够用了。

简单包装模型能力当然危险。模型公司一旦看见价值，很容易自己做。但如果一个产品真的接住了真实任务，它就开始积累模型公司不一定马上拿得到的东西：任务轨迹、用户习惯、工作流数据、组织上下文。

这类数据可能比普通聊天更有价值。聊天记录里有很多情绪、闲聊和低密度问答；Agent 处理真实任务时留下的轨迹，更接近“人到底怎么把事情做完”。

## DAU 不是唯一北极星

移动互联网训练了大家一个习惯：先看 DAU。

AI 生产力产品未必适用。

一个产品如果真的替你干活，最好的状态可能是你不用天天打开它。你把任务交给它，它自己跑，遇到问题再找你确认。这个时候，DAU 下降不一定是坏事，可能说明它真的省掉了你的注意力。

Claude 的 DAU 可能远低于 ChatGPT，但收入价值不一定低。原因很直接：一个高价值任务，比一百次随手打开更值钱。

做 AI 产品时，可能要先问清楚自己优化的是什么。是用户每天打开几次，还是用户愿意把多重要的任务交给你。

## Agent 会改软件的接口

这期还有一个很有意思的判断：软件过去主要服务人，未来也要服务 Agent。

服务人时，GUI 很重要。按钮要清楚，页面要好看，流程要顺。服务 Agent 时，CLI、API、权限、日志、沙盒、支付，可能更关键。

过去的大应用喜欢把用户关在自己的系统里。封闭是护城河。可一旦用户的 Agent 需要访问信息，封闭也会变成阻力。Agent 进不去的地方，用户可能慢慢迁移到更开放的系统。

这件事已经能在一些工具上看到迹象。飞书、命令行工具、开放 API、自动化接口，会让 Agent 更容易进入工作流。未来的软件可能要考虑两种用户：人类用户和 Agent 用户。

## 无限 coding 能力会长出新需求

如果写软件的成本继续下降，会发生什么？

现有软件会被重新做一遍。很多难用的软件，需求一直在，只是过去没有足够好的工程资源去打磨。智能家居、企业内部系统、各种长尾工具，都可能被补一轮。

个性化软件会变多。今天大家用同一个微信、同一个飞书、同一个 CRM。可每个人的使用方式差异很大。等改软件的成本足够低，软件会更像衣服，能按人调整。

一次性软件也会出现。过去低频需求不值得开发。未来为了录一期播客、办一次活动、做一次调研，临时生成一个小系统，可能就够了。

这些需求以前就有，只是开发成本太高。

## 下一个字节可能不像字节

这期谈到字节系创始人时，有个提醒挺扎实：从上一代公司学来的方法，可能要自己颠覆自己。

字节的方法很强。快速迭代、数据驱动、组织密度高、产品和增长能力强。但 AI 时代的产品形态、组织结构、用户入口都在变。过去有效的 DAU 思维、补贴获客、封闭系统、职能分工，未必还能原样迁移。

AI native 公司会更小，团队会更全栈。很多工作不再是前端、后端、设计、测试、运营一条线传下去，而是几个人带着 Agent 负责一个完整模块。

这对老公司不友好。老公司的 context、流程、权限、部门墙都已经长出来了。把 AI 塞进去，难点往往不在“装一个工具”，而在组织愿不愿意改。

## 这期真正有用的地方

我听完之后，记下了几个可以直接检查的问题：

1. 我的产品是在追 DAU，还是在完成高价值任务？
2. 用户为什么留在我这里，而不是直接去模型公司？
3. 我的系统有没有积累真实任务轨迹，而不只是聊天记录？
4. 我服务的是人，还是也能服务 Agent？
5. 我从上一代公司学来的方法，会不会已经变成软肋？

这些问题没有标准答案。  
但如果做 AI 产品，早一点问，比等模型公司下场后再问要好。
